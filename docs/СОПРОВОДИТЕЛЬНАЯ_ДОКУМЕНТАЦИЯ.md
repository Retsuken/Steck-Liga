# СтекЛига — сопроводительная документация

Цифровая платформа-агрегатор ИТ-вакансий с верифицированным профилем достижений участника ФСП.

## 1. Функциональная и компонентная архитектура

Монолит Django с явными слоями:

- **Frontend** — серверные HTML-шаблоны + CSS (`templates/`, `static/css/app.css`), кабинеты кандидата и работодателя.
- **Backend** — приложения `accounts`, `candidates`, `employers`, `testing`, `matching`, `vacancies`.
- **API** — Django REST Framework, OpenAPI 3 через drf-spectacular (`/api/schema/`, `/api/docs/`).
- **Хранение** — SQLite (`data/db.sqlite3`), файлы резюме в `media/`.

Потоки:

1. Кандидат: регистрация email → согласие 152-ФЗ → опрос → уникальный тест → категория.
2. Работодатель: потребность → ранжированная подборка с обоснованием → приглашение (вилка ₽).
3. Кандидат принимает → контакты открываются. Параллельно — публикация вакансий и отклик.

Контейнеризация: `Dockerfile` + `docker-compose.yml`.

## 2. Механика тестирования

Проблемы, которые закрываем:

- Единый тест «утечёт» за день.
- Генерация LLM не гарантирует сопоставимую сложность.

Решение **«стратифицированный банк + уникальная выборка + параметризация»**:

- Задания размечены специализацией, грейдом, навыком, difficulty, discrimination.
- Seed попытки: `profile + spec + grade + timestamp` → разный набор из 8 вопросов, соседние грейды для дискриминативности.
- Параметризованные задачи подставляют числа и пересчитывают ответ; чужой ключ не совпадает.
- Порог 60% — зачёт; 85% — допуск к грейду выше.
- Грейд не понижается принудительно; можно сдать уровень ниже.
- Смена подтверждённой категории — не чаще 1 раза в 90 дней.

## 3. Механика подбора и категоризация

Категория = **специализация + подтверждённый грейд**. Самоописание резюме в выдачу не входит.

Скор относительно потребности:

`0.28·категория + 0.32·тест + 0.20·ФСП + 0.12·стек + 0.08·свежесть`

Нет истории ФСП — штатный ноль по этому члену, кандидат остаётся в выдаче.

Работодатель видит текстовые причины («точное попадание в категорию», «тест 88%», «ФСП 210 очков» / «истории нет»).

Подборку можно сохранить (`SavedShortlist`), чтобы последующие фильтры её не затирали.

Контакт: приглашение с описанием, вилкой «от–до» в рублях, названием компании и способом связи, **без обязательной вакансии**.

## 4. Процедура валидации и результаты

Синтетический набор (seed): 10 кандидатов, 2 потребности.

Команда `python manage.py validate_match`:

- Для потребности «Backend Middle» в топ-3 должны попадать подтверждённые backend middle/senior с высоким тестом и ФСП (Анна, Мария).
- Frontend junior Иван не должен быть выше профильных backend.
- Кандидат без ФСП не отбрасывается, а стоит ниже при прочих равных.

Эталонная разметка пар «потребность — релевантен?» заложена в команде. На демо-данных precision@3 по backend-потребности = 1.0.

Согласованность теста: одна и та же попытка с тем же seed воспроизводит те же формулировки. Повтор с новым seed меняет параметрические ответы — ключ не переносится.

## 5. Интеграция с реестром ФСП

Сейчас: поле `fsp_id` + таблица `FspAchievement` (событие, год, место, очки, дисциплина).

Дальше: Keycloak ФСП ID. Предлагаемый контракт:

- OIDC Authorization Code, claim `sub` → `fsp_id`.
- После логина backend запрашивает реестр `GET /participants/{id}/achievements` (контракт с ФСП уточняется) и синхронизирует достижения.
- Если 404/пустой массив — профиль без истории, UI показывает штатную заглушку.
- Согласия `consent_publish` / `show_fsp` управляют отдачей в API работодателя.

ATS (за рамками MVP, концепция): webhook исходящих приглашений и статусов в формате JSON из OpenAPI; входящий API `POST /api/vacancies/` для публикации из ATS. Антифрод вакансий: верификация домена компании, лимиты приглашений, модерация — после MVP.

## 6. API

Интерактивно: `/api/docs/`  
Схема: `/api/schema/`

Основные методы: `GET /api/me/`, `GET /api/candidates/`, `GET /api/needs/{id}/matches/`, `POST /api/invitations/`, `POST /api/invitations/{id}/decide/`, `GET /api/vacancies/`, `POST /api/applications/`.

Контакты в сериализаторе кандидата отдаются только после accept/отклика.
